## 5. 需要用户拍板

1. **白屏这一版要不要先自用？**
   - 问题：根因未修，但 0.1.1 带原生保底窗口。
   - 选项 A：等根因修复再装；选项 B：先装 0.1.1 自用，根因并行查。
   - 建议：B。保底窗口本来就为这个场景做的，不用它等于没验证。

2. **保底窗口的验证由谁出证据？**
   - 选项 A：你早上自己点一遍，口头反馈；选项 B：Windows 线补一份 TESTPLAN + 截图再交付。
   - 建议：B 为主、A 兜底。没有判据的「能用了」不算验收。

3. **Android 是否计入 v1 放行？**
   - 选项 A：算（画面通了才算 v1 完成）；选项 B：不算（v1 只放 Windows，Android 单独里程碑）。
   - 建议：B。当前连直连客户端都没有，绑进 v1 只会拖住 Windows。

4. **Linux 1080p60 怎么定位？**
   - 选项 A：当缺陷，继续在无 GPU 的 VM 上优化软编；选项 B：写进支持前提（需硬件编码器），不追软编 60。
   - 建议：B，并保留 49 fps 的落盘报告。软编追 60 已被 S7-7 数据否掉。

5. **4 份 TESTPLAN 的元信息谁来补？**
   - 选项 A：执行人补机器与原始日志定位；选项 B：直接标「元信息缺失」结案。
   - 建议：A。补三行成本极低，缺了等于证据链断一半。

6. **`feature/auto-update` 怎么处理？**
   - 选项 A：新开一条自动更新线并登记进分支表；选项 B：并入 Windows 线，删掉独立 worktree。
   - 建议：A。它现在没有独有提交，先登记再决定是否投入。

7. **安装包要不要公开 SHA256？**
   - 选项 A：发布页附校验值；选项 B：不附（当前未签名，靠 SmartScreen 说明）。
   - 建议：A。未签名包最需要哈希自证完整性，成本几行文本。

## 6. 今晚踩到的坑

1. `logs/` 被规则忽略、但文件早已被跟踪，导致「证据查不到」的误判——规则与实际状态不一致。
2. 只在一个 worktree 里搜文件就下「缺失」结论，实际文件在另一条 worktree。
3. 多会话共用主工作树（`observability` 上同时有 Windows 提交和文档提交），违反后来补的 R-T-11。
4. 在一个已经包含目标提交的新分支上 cherry-pick，得到空提交，白跑一轮。
5. PowerShell 把全角引号当字符串定界符，`git commit -m` 被截断成 pathspec 错误。
6. TESTPLAN 只写判据、结果散落在决策记录里，证据链不在同一处。
7. 性能数字同时来自本机回环与 VM，容易被当成跨机结论使用。
8. DDA 0 帧先被当成代码问题，实际先要排除锁屏/会话状态（锁屏已关，仍 0 帧，但排查顺序应固定）。
9. Flutter 原装模板同样白屏这个最小复现做得晚，前期容易误判为业务代码问题。
10. 决策改了（D45 安卓定位），文档没有同步回扫，`03`/`04` 一度与新决策矛盾。
11. 新建 worktree 未同步进分支归属表，出现第 7 条线没人认领。
