## 2. 语义树 / 无障碍：实测数据与未达成说明

### 2.1 已达成（框架侧）

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| `SemanticsBinding.semanticsEnabled` | false | **true** |
| 框架语义节点数（从 root 递归） | 0 | **18** |
| 关键控件语义 | 无 | 按钮/导航/状态卡均有 `label`、`button`、`selected`、`enabled` |

证据方式：临时 Dart 探针写 `%TEMP%\rdc_semantics_probe.txt`，输出 `semanticsEnabled=true ownerExists=true nodeCount=18`（探针在验收后已删除）。

### 2.2 未达成（Windows UIA 侧）

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| UIA `Subtree` 节点数 | 2（`Window 'RDC 远程桌面'` + `Pane 'FLUTTERVIEW'`） | **仍为 2**（rebase 后复测同值） |
| MSAA（`AccessibleObjectFromWindow`） | 1（默认 client 对象） | 1 |

已尝试且均**无变化**的手段（按顺序）：

1. `DartProject::set_accessibility_mode(IAccessibleEx)` + 全量重建。
2. `set_accessibility_mode(IAccessible)`（旧实现）+ 重建。
3. `ensureSemantics()` 从 `runApp` 前改到**首帧之后**（避免平台视图未创建时信号被丢）。
4. 向顶层窗口与 `FLUTTERVIEW` 直接发 `WM_GETOBJECT`（`OBJID_CLIENT` / `UiaRootObjectId`），返回值均为 `0`（无 provider）。
5. 临时打开系统读屏标志 `SPI_SETSCREENREADER=TRUE` 后重启进程（测试后已恢复 `FALSE`）。

结论：本机 Flutter 3.47.9 的 Windows embedder 在此环境下**没有创建 accessibility bridge**（`FlutterWindowsView` 的 `UpdateSemanticsEnabled(true)` 未生效），因此 UIA 只看得到 HWND 容器。这是引擎侧行为，不改协议/传输的前提下无法在应用层绕过。

处置：`main.cpp` 的 `set_accessibility_mode` 覆盖**已回退**（未观测到任何效果，不保留无依据的引擎开关）；Dart 侧语义树与标注**保留**，一旦引擎/读屏激活即可被读到，也是后续自动化测试的基础。

> **无截图、以结构为证**：锁屏状态下 DXGI/掘屏取不到 Flutter 表面（见清单第 1 节实测），本轮证据为 UIA 控件树 + 框架语义节点数。
