## 0. 边界：这份文档管什么、不管什么

- **管**：产物怎么构建、签不签名、用户装的时候会看到什么、我们怎么说明、测试时算什么环境。
- **不管**：某个平台的功能是否达到 v1 支持范围。对外支持范围以 `product/02-需求与验收口径.md` 为准：**v1 对外只承诺 Windows 10/11 x64**。
- 因此本文里的 macOS / iOS / Android 结论，描述的是“**能不能构建、能不能装、装在哪**”，不等于“对外承诺支持”。两个概念不能混着说。

## 1. Windows

### 结论

**不购买代码签名证书。`setup.exe` 与便携 `zip` 均未签名，首次运行会出现 SmartScreen「未知发布者」提示。这是已知、可解释的发布状态，不是缺陷。**

### 能做什么

- 产出 `dist/RDC-<版本>-windows-x64-setup.exe` 与 `RDC-<版本>-windows-portable.zip`，各自带 `.sha256`。
- 未签名状态下可以正常安装、运行、卸载；便携包解压后可直接运行 `rdc.exe`。
- 用户可用 `Get-FileHash <文件> -Algorithm SHA256` 自行核对完整性。

### 不能做什么

- 不能显示可识别的发布者名称；不能消除 SmartScreen 警告。
- 不能保证在受管企业设备上可安装：AppLocker、WDAC、组策略、终端安全软件都可能直接拦截。
- 不提供“关闭 SmartScreen / 关闭杀毒软件 / 改注册表跳过警告”的教程；这类操作风险由用户承担，我们不引导。
- 不把“未签名”包装成“已签名”或“已验证”。

### 用户会遇到什么提示

| 场景 | 提示 |
|---|---|
| 首次双击安装包 | SmartScreen 蓝屏：「Windows 已保护你的电脑」，发布者显示「未知发布者」 |
| 继续安装 | 点「更多信息」→ 出现「仍要运行」按钮 → 才能继续 |
| 安装过程 | UAC 弹窗：「是否允许此应用对你的设备进行更改？」，发布者同样显示未知 |
| 下载时 | 浏览器可能提示「此文件不常下载，可能存在风险」 |
| 受管企业设备 | 「此应用已被系统管理员阻止」或「你的组织已阻止此应用」，且无法用「仍要运行」绕过 |

### 我们怎么规避、怎么说明

1. 安装说明固定写四步：核对 SHA256 → 双击安装 → 遇到 SmartScreen 点「更多信息」→ 点「仍要运行」。
2. 下载页与安装说明明确标注「本版本未签名」，不写「无警告安装」。
3. 企业用户被策略拦截时，说明这是企业策略限制，需由企业 IT 管理员按内部流程加白；我们不提供绕过企业策略的方法。
4. 发布记录里保留每个产物的 SHA256，便于用户和 IT 管理员核对。
5. 若未来购买证书并签名，必须重新发布产物、更新本文与安装说明；不能拿旧哈希对新包。

## 2. macOS

### 结论

**不做 Apple 开发者账号，不做公证（notarization）。本地构建使用 ad-hoc 签名（`codesign -s -`），Gatekeeper 默认会拦截；本地运行需右键「打开」或手动移除隔离属性。**

### 能做什么

- 产出 `dist/RDC-<版本>-macos.dmg`，可安装到 `/Applications`。
- 在开发者自己的机器上，可通过右键「打开」放行；也可用命令移除隔离属性后启动。
- 仅用于本地构建验证与开发自测。

### 不能做什么

- 不能双击直接打开；不能通过 Gatekeeper 的正常评估。
- 不能分发给不受控的普通用户而不出现警告；不能承诺“已签名 / 已公证”。
- ad-hoc 签名不等于 Developer ID 签名，不能替代 Apple 开发者账号。
- 不提供“关闭 Gatekeeper”的系统级教程。

### 用户会遇到什么提示

| 场景 | 提示 |
|---|---|
| 双击 App | 「无法打开“RDC”，因为 Apple 无法验证此 App 是否包含恶意软件」 |
| 右键 → 打开 | 出现「打开」确认按钮，允许本次运行 |
| 较新 macOS | 右键打开后仍可能要求在「系统设置 → 隐私与安全性」里点「仍要打开」 |
| 打开 dmg | 可能提示「此磁盘映像来自未知开发者」 |

### 我们怎么规避、怎么说明

安装说明写两条路径，并给出可复制的命令：

```bash
# 只移除下载的 dmg 的隔离标记（按实际文件名替换）
xattr -d com.apple.quarantine ~/Downloads/RDC-<版本>-macos.dmg

# 或移除已安装 App 的隔离标记
xattr -dr com.apple.quarantine /Applications/RDC.app
```

说明要点：

1. 命令只移除隔离标记，不改变签名，也不代表已通过 Apple 验证；需用户主动执行。
2. 不把 `xattr` 命令写进安装包自动执行，不在用户不知情时修改系统状态。
3. 文档统一写「未公证，首次打开需右键打开或移除隔离属性」；禁止写「双击即可」「已适配 Gatekeeper」。
4. macOS 产物不作为 v1 对外支持范围，下载页不得把它列成“正式支持平台”。

## 3. iOS

### 结论

**不签名。iOS 产物只能在模拟器运行；真机无法安装。“iOS 真机不在支持范围”是明确结论，不写成“应该可以”。**

### 能做什么

- 构建 iOS 模拟器产物，在 Xcode 模拟器中启动、调试界面。
- 用模拟器验证 Flutter 页面与交互。
- 模拟器验证不代表远控链路可用；采集与注入能力是否达标，仍按 `docs/10` 的阶段验收判断。

### 不能做什么

- 不能安装到 iPhone / iPad 真机；未签名的 `.app` / `.ipa` 在真机上无法安装。
- 不能走 TestFlight、App Store、企业分发或 Ad Hoc 分发。
- 不提供真机安装教程、不提供“签名后就能用”的暗示。
- 不承诺“iOS 客户端可用”，真机不在 v1 及当前支持范围。

### 用户会遇到什么提示

| 场景 | 提示 |
|---|---|
| 尝试真机安装 | 安装失败，提示应用未签名 / 需要开发者证书或描述文件 |
| 尝试打开未签名 ipa | 无法安装；部分工具会提示「此应用未经过签名」 |
| 开发者模式 | 即使开启开发者模式，也不能替代签名与描述文件 |

### 我们怎么规避、怎么说明

1. 文档、下载页、客服口径统一写「iOS 真机不在支持范围；仅模拟器可用于开发验证」。
2. 不把未签名 `.ipa` 作为“可安装产物”发布；仓库里的 iOS 构建脚本产物只用于模拟器/构建验证，不对外提供安装包。
3. 禁止说法：「应该可以装」「签个名就行」「越狱后可装」；统一回复「不支持真机」。
4. 如用户提出真机需求，记录为后续需求，不在当前版本给承诺。

## 4. Android

### 结论

**不上架任何应用商店。使用 debug 签名产出 APK，可直接安装到真机；不提供正式签名包，也不做“正式版/商店版”承诺。**

### 能做什么

- 产出 debug 签名 APK（按 ABI 拆分），用于内部验证。
- 真机安装：允许「安装未知来源」后直接安装，或用 `adb install -r`。
- 可在真机上验证页面启动与基础交互。

### 不能做什么

- 不上架 Google Play、国内应用商店；不提供商店链接。
- 不提供 release / 正式签名的 APK 或 AAB；不承诺签名稳定性与覆盖升级。
- 不做“正式发布包”表述；debug 包不是正式版本。
- 仓库打包脚本保留 release 签名路径，但**当前发布口径不启用**；不得把 debug 包描述为正式版。

### 用户会遇到什么提示

| 场景 | 提示 |
|---|---|
| 安装 APK | 「此应用来自未知来源」/ 要求开启「允许安装未知应用」 |
| Play Protect | 「此应用未经 Play 保护机制检测」 |
| 国产 ROM | 可能被「纯净模式」「安全检测」拦截，需要手动允许 |
| 覆盖安装 | 若 debug 签名变化（换机器、清理构建），会提示签名不一致，必须先卸载 |

### 我们怎么规避、怎么说明

1. 文件名带 `debug`，例如 `RDC-<版本>-android-arm64-v8a-debug.apk`，避免被误认成正式包。
2. 说明写清：内部测试包、非商店版本、不保证长期升级；安装需允许未知来源。
3. 提供 SHA256；安装步骤写「设置 → 允许此来源安装 → 安装」，或 `adb install -r <apk>`。
4. 签名变化导致覆盖安装失败时，说明需卸载重装（本地数据会丢失），不把它当成缺陷。
5. 不写「正式签名」「可上架」「应用商店下载」等承诺。

## 5. 开源许可与编解码 SDK

### 结论

- 项目自身代码：MIT。
- FFmpeg：**LGPL 动态链接**，不启用 GPL 组件；默认产物不含 FFmpeg DLL。
- NVENC / AMF / oneVPL：遵循各自 SDK 条款，不超出许可范围重分发。

### 能做什么

- 以动态链接方式使用 LGPL 版 FFmpeg；用户可替换同版本 DLL。
- 默认构建不带 FFmpeg；需要时按 `--features ffmpeg` 自行构建并遵守 LGPL。
- 使用 NVENC / AMF / oneVPL 时，按其 SDK 条款调用与分发运行库。
- 安装包内附 `LICENSE` 与 `THIRD_PARTY_NOTICES.md`，关于页可查看许可说明。

### 不能做什么

- 不把任何 GPL 编码器组件打进发布包；不开启 `--enable-gpl`。
- 不静态链接 LGPL 库到无法替换的程度；若修改了 FFmpeg 源码，必须按 LGPL 提供对应源码。
- 不声称“整个产品都是 MIT”；不把第三方 SDK 的运行库当成可随意再分发。
- 不对 SDK 条款做法律解释；条款以各 SDK 随附许可为准。

### 用户会遇到什么提示

| 场景 | 提示 |
|---|---|
| 默认安装包 | 不含 FFmpeg，部分编码路径不可用；关于页会列出第三方组件 |
| 自行构建 FFmpeg | 构建说明提示 LGPL 义务与动态链接要求 |
| 使用硬件编码 | 依赖 NVIDIA / AMD / Intel 驱动与对应 SDK 运行库，缺驱动时功能不可用 |

### 我们怎么规避、怎么说明

1. 打包检查：默认 Release 目录出现 `av*.dll` 直接失败（现有打包脚本已做此校验）。
2. 许可扫描：发布前检查构建参数不含 `--enable-gpl`，产物不含 GPL 组件。
3. FFmpeg 以独立 DLL 形式分发时，保留版权与许可文本，并说明可替换；修改过源码则按 LGPL 提供对应源码。
4. NVENC / AMF / oneVPL 的运行库与许可文本随包附带，发布前由发布负责人逐项复核 SDK 条款；不复核不发布。
5. 关于页写“本项目 MIT；第三方组件各自适用其许可”，不写“全部开源免费”。

## 6. 平台总表

| 平台 | 产物 | 签名状态 | 安装方式 | 支持范围 |
|---|---|---|---|---|
| Windows | `setup.exe` / 便携 `zip` | 未签名，无证书 | SmartScreen「更多信息 → 仍要运行」；便携包解压即用 | **v1 对外支持** |
| macOS | `dmg` | ad-hoc 签名，未公证 | 右键「打开」或 `xattr` 移除隔离属性 | 仅本地验证，不对外承诺 |
| iOS | 模拟器构建产物 | 不签名 | 仅在 Xcode 模拟器运行 | **真机不在支持范围** |
| Android | `*-debug.apk` | debug 签名 | 允许未知来源后安装 / `adb install -r` | 仅内部验证，不上架 |

## 7. 发布前检查清单

- [ ] Windows：安装说明含 SHA256 核对与「更多信息 → 仍要运行」；全站无“无警告安装”表述。
- [ ] Windows：企业策略拦截的说明已写入下载页/FAQ，未提供绕过方法。
- [ ] macOS：dmg 为 ad-hoc 签名；安装说明含右键「打开」与两条 `xattr` 命令；无“已公证”表述。
- [ ] iOS：对外只说明模拟器验证；未签名 ipa 不作为可安装产物发布；文案无“应该可以”。
- [ ] Android：APK 文件名含 `debug`；无商店链接、无正式签名承诺；覆盖安装失败已说明需卸载。
- [ ] 许可：默认包不含 FFmpeg DLL；构建参数无 `--enable-gpl`；`LICENSE` 与 `THIRD_PARTY_NOTICES.md` 随包。
- [ ] 许可：NVENC / AMF / oneVPL 条款已由发布负责人复核并留记录。
- [ ] 所有产物附 `.sha256`，哈希与产物同批生成。

## 9. 与 03 号测试文档的同步

本次只在 `product/03-测试要点.md` 的「1. 环境与准备」补充环境分类，并同步放行说明，不改变任何已有用例的判据：

- Windows 未签名 = 有效测试环境；SmartScreen 按本文口径操作并留证。
- 企业策略拦截 = BLOCKED（环境限制），换非受管机器复测，不算产品缺陷。
- macOS 未公证 = 有效环境，但仅限本地验证。
- iOS 模拟器 = 有效环境；iOS 真机 = N/A（不在支持范围），不计 PASS/FAIL。
- Android debug 真机 = 有效环境，仅限内部验证。
