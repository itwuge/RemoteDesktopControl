RDC 远程桌面 · 诊断说明

错误码与自助排查

适用版本 0.1.1 及以后 · 页面关键字：RDR-001、白屏、渲染初始化失败、被控端黑屏

一、错误码表

错误码用户可读名称触发条件表现
RDR-001 渲染初始化失败 进程启动后 3 秒内没有完成首帧呈现。按实际根因分四种，第一条最常见：
  • no_display_output：本机没有活跃显示输出——显示器关闭、进入睡眠、线缆未连接，且没有虚拟显示器。此时桌面不再产生新画面，渲染与采集都拿不到内容；
  • render_not_visible：有显示输出，但 3 秒内渲染通道没有产出可见画面；
  • init_failed：Flutter 渲染控制器没有创建成功；
  • forced_for_test：仅用于抓屏验收，设置 RDC_FORCE_FALLBACK=1 时触发。
no_display_output 与 render_not_visible 共用 RDR-001， 但原因码分开记录，日志里可直接检索。 		主窗口保持可见（可能只有一片白），软件仍在运行；保底窗口叠加在主窗口之上接管显示。

错误码是稳定编号，用于检索与反馈；诊断文本里的触发条件只写中文原因，不出现英文异常名或 HRESULT 原值。

二、看到 RDR-001 时，按这四步处理

第一步最常见：确认被控端有活跃显示输出。 显示器关闭、拔掉线缆或进入睡眠时，系统没有活跃显示输出，桌面不再产生新画面： 主界面会白屏，远控画面会黑屏。ToDesk、向日葵都把它列为常见原因，但用户通常想不到。 本版本不提供虚拟屏。
  1. 确认被控端显示器处于开启、已连接状态。可执行动作：打开显示器；没有显示器时接一个 HDMI 假负载（dummy plug）；或启用虚拟显示器 （例如远程工具自带的虚拟屏）。
  2. 点保底窗口里的「用兼容渲染重试」。它会关闭 Impeller、改用 Skia（ANGLE / D3D11）并在当前进程内重新初始化渲染，不需要重装、不需要重启电脑。 成功后设置页的「渲染模式」会显示当前渲染：兼容模式。
  3. 更新或回滚显卡驱动后重启。打开「设备管理器 → 显示适配器 → 右键显卡 → 更新驱动程序」； 如果这个问题是刚更新过显卡驱动才出现的，请回滚到上一个版本的驱动。
  4. 点「复制诊断」把内容发给我们，或点「打开日志目录」自己查看。 诊断文本包含显卡型号、驱动版本、WDDM、渲染后端、错误码和日志路径，不包含密码、配对码或屏幕内容。

三、诊断文本里各项的含义

字段说明
错误码 / 触发条件RDR-001 与对应的 no_frame / blank / init_failed。
渲染后端当前使用的是 skia、impeller 还是 skia(compat)，以及第几次尝试。
显卡 / 驱动版本 / 驱动日期取自 DXGI 与注册表，用于核对驱动是否为已知问题版本。
显卡 BIOS部分改版 BIOS 会导致「D3D11 正常但显示输出异常」，可与官方 BIOS 对比。
WDDM注册表 GraphicsDrivers\WddmVersion 的原始值。
会话类型本地会话还是远程会话，用于排除远程桌面显卡限制。
最近 5 条事件启动日志的末尾 5 行，含渲染初始化与重试记录。

四、边界与常见误判

  • 白屏不等于软件崩溃：进程仍在运行、日志仍在写入，保底窗口就是为此准备的。
  • 保底窗口由 Win32 原生控件绘制，不经过 Flutter；主界面白屏时它仍然可以显示和截图。
  • 「被控端黑屏」先查显示输出状态：RDR-001 的 no_display_output 就是这一条； 排除显示输出后，才按 render_not_visible 继续排查。
  • 远程工具（ToDesk、向日葵等）自身捕获失败也会表现为黑屏，可用本机截图交叉验证。
