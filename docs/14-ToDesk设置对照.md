## 2. 与现有设计文档的差异

### 2.1 ToDesk 有、我们未设计（或未落到 UI）

| # | ToDesk 项 | 我们的现状 | 建议 | 理由 |
|---|---|---|---|---|
| 1 | 开机自动启动 | 未设计（01/02 无启动项） | **采纳（v1）** | 被控端常驻是可用性前提，成本极低 |
| 2 | 防止电脑休眠 | 未设计；13 有"本机被控时屏幕常亮"但仅覆盖会话期 | **采纳（v1）** | 无人值守场景必需；与 06 采集稳定性相关 |
| 3 | 文件默认存储路径 / 更改目录 / 打开目录 / 完成后自动打开 | 08 只写"落到默认下载目录"，无 UI 细节 | **采纳（v1）** | 文件传输 v1 已有，路径选择是必要配套 |
| 4 | 文件传输主目录默认打开（上次位置/自定义） | 未设计 | 不采纳（v1） | 细节优化，收益低 |
| 5 | 远程打印 | 未设计 | **不采纳（v1）**，列远期 | 需打印机驱动虚拟化，跨平台成本极高 |
| 6 | 录屏（自动/无水印/硬编/存储路径） | 未设计 | 不采纳（v1） | 与"低延迟/低占用"目标冲突，且涉及合规与存储；可二期 |

### 2.3 结论性判断

1. **ToDesk 的强项是"开箱可用的默认值 + 细碎但实用的本地体验项"**（启动、休眠、路径、提醒、锁屏、剪贴板开关、鼠标缩放）。这些我们**缺得最多**，且都是低成本项，应优先补。
2. **ToDesk 的弱项是"可验证性与细粒度授权"**：没有延迟口径、没有权限位、没有审计。这是我们真正的差异化，不应为了对齐而放弃。
3. **明确不跟的项**：远程打印、录屏、虚拟屏、3D 鼠标、聊天、投屏/应用中心/增值入口。这些会把 v1 关键路径拖长，且与"低延迟远控"主线无关。
4. **需要用户决策的项**：临时密码作为第二连接入口（低摩擦 vs 安全模型一致性）；隐私屏是否进 v1。

### 4.8 借鉴建议：新手引导、一键锁定远程访问

| 能力 | 建议 | 理由 | 代价 |
|---|---|---|---|
| **新手引导（快速上手）** | **采纳，但降级为轻量版，排在 S5 之后**（不阻塞 v1） | ① 我们的首连门槛比 ToDesk 高：设备代码 + 配对码 + 信任决策 + 权限位，用户更容易卡住；② 引导是"可量化的减阻"，用 6 个可判定任务即可覆盖；③ ToDesk 已验证"任务清单 + 红点 + 进度"的留存价值 | ① 需要 6 个**可判定完成状态**的埋点（允许访问开启 / 查看设备代码 / 首次连接成功 / 收藏设备 / 移动端或跳过 / 设置配对码），涉及产品口径与事件上报，属跨端工作；② 需要抽屉组件 + 引导高亮组件（截图热点定位在 Flutter 上要用 Overlay + 锚点注册，约 2 个自绘组件）；③ 维护成本：每次 UI 改版都要同步锚点与文案。<br>**结论：不做 ToDesk 那种"每项 3 小步的截图图解"，只做 6 行任务清单 + 一键跳转，成本可压到 1/3。** |
| **一键锁定远程访问** | **拆成两个能力，都采纳**（v1） | 用户口语里的"一键锁定远程访问"其实混了两件事：<br>① **锁客户端 UI**（ToDesk 锁形图标）：防止他人操作本机设置，属本地防护；<br>② **紧急停止远程访问**（ToDesk 没有）：立即关闭"允许控制本设备"并断开全部会话，属知情权与安全的兜底。ToDesk 只有 ①，没有 ② —— 这正是我们可以做差异化的点 | ① 锁客户端：复用系统密钥库 + 生物识别，工作量≈1 个锁屏 View + 1 个解锁流程，成本低；<br>② 紧急停止：需定义原子语义（关闭开关 + 断开所有会话 + 置 `access_revoked` + 写审计 + 通知在线控制者），要处理"误触后如何恢复"（重新开启仍需本机确认）；<br>③ 无人值守设备误触会导致**彻底失联**，必须"本地二次确认 + 保留物理键/托盘可恢复"，这会引入一个"最近一次停止原因"状态位；<br>④ 与 13 号并发模式、接管流程有交叉，需要明确"停止时正在接管的会话是否一并终止"（建议：一并终止，并记为 revoke 事件）。 |

**落点建议**

- 锁客户端 → 13 号⑥「本机保护区」新增一行「立即锁定客户端」，并在标题栏常驻图标；
- 紧急停止 → 13 号①「总开关区」新增「立即停止远程访问」（红色危险按钮，二次确认），与总开关互斥展示（开启时显示"停止"，关闭时显示"允许"）；
- 新手引导 → 独立 `onboarding` 模块，不塞进设置页；红点挂在主界面标题栏。

### 5.3 我们的建议：模式胶囊 + 内容区（上下单栏）

**结构**

```
┌──────────────────────────────────────────────┐
│ 标题栏：应用名 · 连接状态 · 允许访问开关(镜像) · 锁/通知/菜单 │
├──────────────────────────────────────────────┤
│ 胶囊行：远程控制 | 屏幕墙 | 设备 | 文件传输    │  ← 单行，选中蓝底白字
├──────────────────────────────────────────────┤

│  · 远程控制：设备代码/临时码 + 连接输入 + 模式单选  │
│  · 屏幕墙：4/9/16 宫格        · 设备：列表 + 详情  │
│  · 文件传输：拖拽区 + 传输记录                  │
└──────────────────────────────────────────────┘
```

| 决策 | 建议 | 理由 |
|---|---|---|
| 是否用胶囊 | **用**，4 个：远程控制 / 屏幕墙 / 设备 / 文件传输 | 这四个是**并列的"我要做什么"**，不是层级导航；胶囊比左侧导航少一层跳转，且窗口宽度 900 级别时左侧导航挤占内容区 |
| 是否保留左侧导航 | **不保留**（或用极窄图标栏只放"高级设置/账号"） | ToDesk 左侧导航与胶囊同时存在，视觉上重复（设备列表 / 屏幕墙 在两处都有入口）；我们应"一种层级只用一种控件" |
| 是否做场景切换 | **不做** | 场景会连带改导航与胶囊集合，是 IA 级复杂度；我们只有"远控 + 多设备"一条主线 |
| 是否做快速设置 | **做，但作为第 5 个胶囊或右上角按钮**，内容区展示 6~7 项 | 高频项不值得进设置页；且用内容区而非弹层，可与设置页共享 Model |

### 5.4 与 12 号、13 号如何共存（避免入口重复）

| 冲突点 | 规则 |
|---|---|
| 屏幕墙：13 号设置页 vs 12 号主界面 | 屏幕墙**只在胶囊里**作为内容模式；设置页只保留其"预览流参数/布局默认值"（放"连接与显示"页）。屏幕墙本身**不进左侧导航、不进设置页**。独立窗口形态改为胶囊内右上角「弹出独立窗口」按钮，不做第二个入口。 |
| 设备列表：胶囊 vs 导航 | "设备"胶囊 = 列表 + 右侧详情（同 ToDesk 布局）。**不再**在设置页放"设备管理"；设备增删改在胶囊内完成。 |
| 允许访问开关：主页 vs 13 号① | **13 号①是权威写入点**，标题栏/主页的开关只是**只读镜像 + 快捷写入**；两者共用一个 Model 与一个命令通道，切换后所有镜像同步刷新（避免两处状态不一致）。 |
| 权限/授权管理 | **不进主界面**。唯一入口是"高级设置 → 远程访问权限"（13 号）。主界面最多提供一个 `管理权限 >` 文字链，不出现"授权"二级入口。 |
| 快速设置 vs 高级设置 | 快速设置只允许**高频可写子集**（上表 7 项）；同一字段在两处出现时必须同 Model；其余项只能"更多设置 >"跳转，不允许复制第二份 UI。 |
| 通知铃铛 vs 12 号设备上/下线提醒 | 铃铛只承载**事件型通知**（设备上线/离线、连接建立/断开、授权变更、接管申请）。系统级"右下角弹窗"由"常规 → 通知"页控制开关，铃铛不再重复开关。 |
| 新手引导 | 独立模块，红点挂在标题栏"快速上手"位置；**不在设置页出现**，也不做成 Welcome 一次性弹窗（可跳过且可再次打开）。 |
