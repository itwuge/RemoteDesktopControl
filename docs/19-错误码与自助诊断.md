## 0. 这份表怎么用

1. **一码一说明**：任何面向用户可见的失败，必须在本表登记一条完整记录；没有记录的码不允许出现在界面上。
2. **码不复用、不删除**：废弃的码保留记录并标「已废弃（替代码 RDR-xxx）」，便于用户搜索历史帖子。
3. **两套信息分开写**：
   - 「用户能看到什么」= 界面上真实出现的文案，逐字照抄，不允许写“提示用户稍后重试”这种概述；
   - 「日志里应有什么」= 结构化字段与事件名，供排查与自动分析。
4. **敏感信息红线**：错误码、界面文案、复制出的诊断文本、日志，一律不得包含密码、配对码、会话密钥、令牌、远程画面内容、剪贴板内容。
5. **编号规则**：`RDR-NNN`，三位数字按模块分段（见第 1 节）；同一码在不同平台含义必须一致，平台差异放字段。
6. **落地要求**：新增用户可见失败路径时，错误码与帮助文案随功能一起提交；缺码的缺陷不得关闭（见 D47）。

## 3. RDR-001 渲染初始化失败（完整条目）

### 3.1 基本信息

| 项 | 内容 |
|---|---|
| 编码 | `RDR-001` |
| 名称 | 渲染初始化失败（主窗口未在限定时间内产出首帧） |
| 严重级别 | S1（用户完全无法使用，等价于“软件打不开”） |
| 所属模块 | GUI 启动 / 渲染后端 |
| 首次确认版本 | Windows 安装包（Flutter 3.47.9 构建），2026-11-08 实测 |
| 已知复现环境 | AMD RX 580 2048SP；同机 `flutter create` 原装模板同样白屏，判定为环境级渲染问题 |
| 关联需求 | `product/02` R-33（P0，v1 是） |
| 关联用例 | `product/03` T-33 |
| 关联决策 | D46（保底窗口升为一等功能）、D47（错误码纳入交付标准） |
| 状态 | 已定义 · 未实现 |

### 3.2 触发条件

判定口径统一为**结果条件**，不绑定具体驱动错误或底层异常：

- **进程存活（未退出、未崩溃）但 3 秒内主窗口未完成首帧呈现**（白屏、全黑或无窗口），即判定为 `RDR-001`。该口径已同步给 Windows 线执行。
- 典型成因（用于日志归类，不作为判定依据）：
  1. 图形上下文 / 渲染后端初始化失败（驱动或 ANGLE 一类中间层创建失败）；
  2. 显卡驱动不兼容、驱动被禁用或处于异常状态；
  3. GPU 进程崩溃或反复重启；
  4. 虚拟机 / 远程会话中无可用 GPU 输出；
  5. 渲染线程挂起但进程仍存活（界面无响应、纯白）。
- **不触发**：主窗口已显示、仅个别控件异常（另立码）；用户主动最小化到托盘（不是故障）。

### 3.3 用户能看到什么

保底窗口由**非 Flutter 通道**绘制（原生控件或等价实现），文案逐字如下：

- 标题：`程序界面无法显示（RDR-001）`
- 正文第一行：`界面渲染初始化失败，主窗口没能显示出来。`
- 正文第二行：`这不是你的操作问题，也不是网络问题。可以按下面三步处理。`
- 按钮（三个，顺序固定）：
  1. `用兼容渲染重试`
  2. `复制诊断`
  3. `打开日志目录`
- 底部小字：`诊断信息只包含版本、显卡和错误记录，不包含密码、配对码或你的屏幕内容。`

约束：

- 不显示堆栈、英文异常名、`hresult` 原值（原值只进日志）。
- 不显示“请重试”这类空话；每个按钮都必须真的能点、真的有效果。
- 窗口必须可拖动、可关闭；关闭时不弹二次挽留。

### 3.4 三条自助步骤（界面与帮助页同文）

1. **先点「用兼容渲染重试」**：切换渲染方式后重新初始化，不需要重装、不需要重启电脑。成功会直接进入主界面，设置页显示「当前渲染：兼容模式」。
2. **更新或回滚显卡驱动后重启**：打开设备管理器 → 显示适配器 → 右键显卡 → 更新驱动程序；若刚更新过驱动才出现此问题，回滚到上一版本驱动。
3. **点「复制诊断」把内容发给我们，或点「打开日志目录」自己查看**：诊断文本含错误码、时间、版本、平台、显卡型号与驱动版本、最近 5 条事件。

补充说明（帮助页可写，保底窗口不写）：若三步都无效，可先把软件装到另一台机器完成手头的事；该问题会以 `RDR-001` 跟进，不需要用户自行改注册表、关杀毒软件或安装第三方运行库。

### 3.5 日志里应有什么

遵循 `docs/16` 的结构化事件规范（JSONL + 人读双份，字段字典见 §2.3，敏感字段过滤由 `redact` 统一处理）。

必填事件：

| 事件名 | 触发时机 | 必填字段 |
|---|---|---|
| `render.init_start` | 渲染初始化开始 | `ts`、`event`、`app_version`、`platform`、`renderer_backend` |
| `render.init_failed` | 判定失败（3 秒未出首帧或底层报错） | 追加 `diag_code=RDR-001`、`cause`（归类值）、`hresult`（如有）、`elapsed_ms`、`attempt` |
| `render.ready` | 首帧成功呈现 | `ts`、`event`、`elapsed_ms`、`renderer_backend` |
| `render.retry` | 用户点「用兼容渲染重试」 | `ts`、`event`、`from_backend`、`to_backend`、`attempt` |
| `render.fallback_shown` | 保底窗口显示 | `ts`、`event`、`diag_code`、`log_dir` |
| `diag.export` | 用户点「复制诊断」 | `ts`、`event`、`diag_code`、`bytes`（导出文本字节数） |

环境字段（`render.init_failed` 必须带全）：`gpu_vendor`、`gpu_model`、`driver_version`、`os_build`、`app_version`、`session_type`（本地 / 远程会话 / 虚拟机）。

示例（字段名以 `docs/16` 字典为准，此处只示意结构）：

```json
{"ts":"2026-11-08T10:12:03.441+08:00","level":"error","event":"render.init_failed","diag_code":"RDR-001","cause":"graphics_context_create_failed","hresult":"0x887A0005","elapsed_ms":3012,"attempt":1,"renderer_backend":"angle_d3d11","gpu_vendor":"AMD","gpu_model":"Radeon RX 580 2048SP","driver_version":"31.0.21921.1000","os_build":"22631","app_version":"0.1.0","session_type":"local"}
```

红线：日志与诊断文本均不得出现密码、配对码、会话密钥、令牌、远程画面、剪贴板内容；`log_dir` 只输出目录路径，不输出目录内其他文件名清单。

### 3.6 复现与验证

- **复现机**：AMD RX 580 2048SP + Flutter 3.47.9 构建的安装包，双击启动即复现。
- **补充路径**：禁用/卸载显卡驱动后启动；或在虚拟机中关闭 GPU 加速后启动。
- **期望**：≤3 秒出现保底窗口（含 `RDR-001` 与三个按钮）→ 点「复制诊断」得到文本 → 点「打开日志目录」定位到真实日志 → 点「用兼容渲染重试」≤10 秒进入主界面 → 设置页显示「当前渲染：兼容模式」。
- **判据归属**：`product/03` T-33；本表只提供文案与字段标准。

### 3.7 常见误判

| 用户以为 | 实际 |
|---|---|
| “软件在加载，再等等” | 超过 3 秒仍是纯白即 `RDR-001`，不会自己好 |
| “我网不好” | 该阶段尚未建立任何连接，与网络无关 |
| “电脑中毒了” | 判定为渲染初始化失败，有明确错误码与日志 |
| “重装就好” | 重装通常不改变渲染环境；优先点「用兼容渲染重试」 |

### 3.8 明确不做

- 不引导用户关闭杀毒软件、关闭 SmartScreen、修改注册表或安装第三方运行库。
- 不在保底窗口里提供“以管理员身份重新运行”这类无效建议（除非后续有实测证据支持）。
- 不把 `RDR-001` 复用到其他启动失败（如缺少 DLL、安装损坏），它们另立码。

## 5. 维护流程

1. **提报**：模块 owner 在实现用户可见失败路径前，先在 PR 描述里给出码号、用户文案、日志字段。
2. **审核**：产品经理核对文案（是否人话、是否可行动、是否有未实现承诺）；设计/文档负责人核对字段是否符合 `docs/16`。
3. **登记**：合并时同步更新本表与错误码总表；未登记不予合并。
4. **变更**：改文案要同步改本表与帮助页；改码号按“旧码标记废弃 + 新码新增”，保留映射。
5. **回收**：连续两个版本未触发的码不删除，标「低频」，用于判断是否值得保留保底路径。
