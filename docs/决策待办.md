## D1 Windows 插件符号链接 / Flutter 插件方案

- **问题**：本机未开启 Windows 开发者模式（无管理员权限），`flutter pub get` 无法为
  path 插件创建符号链接，因此无法使用 flutter_rust_bridge 官方 `integrate` 生成的
  `rust_builder` 插件（cargokit）。
- **可选方案**：
  1. 开启 Windows 开发者模式（需管理员权限），恢复 cargokit 插件方案；
  2. 维持当前方案：不引入插件，由 CMake 钩子与打包脚本显式构建/复制动态库。
- **影响**：方案 1 开发体验最好，但需要系统设置变更；方案 2 已在 S1 打通，跨平台布局需
  各平台脚本分别维护（Windows/Linux CMake 钩子，macOS/iOS/Android 打包脚本）。
- **建议**：长期采用方案 1（官方插件），短期保留方案 2 保证 CI 与本地均可构建。
- **临时处理**：方案 2，已通过 `cargo build` + `flutter build windows` 验证。
- **是否阻塞**：不阻塞 S1；S2 起如引入第三方 Flutter 插件（托盘、剪贴板）会遇到同一限制。

## D2 Android keystore 归属与密码

- **问题**：正式 APK 签名需要固定 keystore；目前无凭据。
- **可选方案**：由项目负责人生成并保管 keystore，写入 GitHub Secrets
  （`ANDROID_KEYSTORE_BASE64` / `ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_ALIAS`）；
  或继续使用 debug 签名做内部验证。
- **影响**：debug 签名产物不能上架应用商店，且不同机器签名不一致会导致覆盖安装失败。
- **建议**：S2 结束前生成正式 keystore 并入库 Secrets。
- **临时处理**：`packaging/android/build_apk.sh` 检测凭据，缺失时使用 debug 签名并在日志告警。
- **是否阻塞**：不阻塞构建；阻塞"可分发 Android 包"。

## D3 iOS 签名、开发者账号与公证

- **问题**：iOS 真机分发需要 Apple 开发者账号、证书与描述文件；macOS 公证需要开发者 ID。
- **可选方案**：提供 `IOS_TEAM_ID` 与证书 secrets；或仅交付无签名 xcarchive 供持有账号者自行签名。
- **影响**：无签名产物只能用于模拟器/越狱设备，无法直接安装。
- **建议**：先交付无签名 xcarchive，发布前再补证书。
- **临时处理**：`packaging/ios/build_xcarchive.sh` 使用 `--no-codesign`，日志明确说明降级。
- **是否阻塞**：不阻塞 S1；阻塞"可安装 iOS 包"。

## D4 iOS Rust 静态库链接方式

- **问题**：iOS 不允许 `dlopen` 任意动态库，FRB 需以 staticlib 形式链接进 Runner；
  但当前未修改 Xcode 工程（`project.pbxproj`）添加链接参数与构建阶段，属高风险自动改动。
- **可选方案**：
  1. 用 FRB 官方插件（同 D1，需要开发者模式/官方 Xcode 集成）；
  2. 手工在 Xcode 工程添加 Run Script + `OTHER_LDFLAGS`（机器可复现，但改工程文件风险高）；
  3. S2 再引入官方 iOS 集成文档步骤，由负责人评审后实施。
- **影响**：当前 iOS 可构建归档，但运行时 Rust 核心不可用（首页会显示"核心加载失败"）。
- **建议**：采用方案 2 并在 CI 验证归档后链接产物；需负责人确认改动 Xcode 工程。
- **临时处理**：iOS 仅保证 `xcarchive` 可产出，首页错误横幅明确告知。
- **是否阻塞**：阻塞 iOS 端"显示版本号"验收；不阻塞其它平台。

## D5 移动端设置持久化目录

- **问题**：为避免引入 `path_provider` 插件（同 D1），移动端设置暂存于系统临时目录，

- **可选方案**：允许引入 `path_provider`（需 D1 方案 1）；或 Android 用 Java 侧
  `getFilesDir` 通过 MethodChannel 暴露给 Dart。
- **影响**：S1 不涉及业务配置，影响仅在设置页保存。
- **建议**：S2 前落定 D1 后使用 `path_provider`。
- **临时处理**：`SettingsRepository` 在移动端回退到 `Directory.systemTemp`，代码内已注明。
- **是否阻塞**：不阻塞 S1。
