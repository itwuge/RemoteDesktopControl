## 本项目专属：7 处文档口径矛盾的裁定

裁定优先级（高到低）：

1. **有实测数据**，以实测为准（`logs/` 里有验证记录）；
2. 没有实测，**以最新决策记录为准**（`docs/决策待办.md` 编号大者优先）；
3. 还是没有，**以描述最详细、最具体的那份文档为准**；
4. 三条都用不上，登记待办，写清"需要什么数据才能定"与负责线。

以下逐条给出「裁定结果 + 依据 + 依据出处」；涉及源文档的，源文档口径已同步改到一致（只改口径文字，不改代码）。

**证据规则（R-D-12）**：凡是涉及常量数值的裁定，必须附**代码文件名 + 行号**，不得只写"依据实现"；两处数值不一致且未核对到代码时，只能标「待代码核对」，不得写成已定。本页第 1 条即按此规则处理。

### 1. 单包载荷上限：1352 / 1344 / 1339（**待代码核对**）

> **状态：待代码核对，未定。** 两条线给出了两个不同的分片头长度，只能有一个对。核对完成前，本节不作为已定口径引用。

### 5. 默认解码器：FFmpeg 还是 MF

- **裁定结果**：不存在脱离构建条件的"默认解码器"。口径统一为：
  - **源码 / 运行期**：以 `ffmpeg` feature 构建时，`DecoderBackend::from_env()` 默认 FFmpeg（d3d11va）；`RDC_DECODER=mf` 始终是回退。未启用 feature 或无 FFmpeg 构建时为 MF。
  - **发布包**：默认构建不含 FFmpeg（`product/04`），此时实际默认是 MF；唯一判据是 `BUILD_INFO.txt` 的 `ffmpeg=on/off`。
  - 文档禁止笼统写"默认 FFmpeg"，必须带"以 `ffmpeg` feature 构建时"或"见 BUILD_INFO"。
- **依据（优先级 ① 实测 + ② 最新决策）**：D36 实测"不带任何环境变量跑 `s3b4`，`decoder_path=ffmpeg`"（前提是 `--features ffmpeg`）；D36 编号大于 D35（D35 的"未设默认"已被 D36 取代）；S7 口径同向；打包脚本在无自建 FFmpeg 时强制 MF 并写 `ffmpeg=off`。
- **依据出处（代码行号必附）**：`crates/rdc-decode/src/video_decoder.rs:35-50`（`from_env()`；`:40-47` 按 `cfg(feature = "ffmpeg")` 取默认）；`docs/决策待办.md` D36（第 401-410 行）、S7 实现落地（第 719-723 行）；`product/04` 第 188、194、209、241 行；`packaging/windows/build_installer.ps1` 第 35、154、219、232 行。
